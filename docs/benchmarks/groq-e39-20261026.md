# Groq Phase 3: real BMW E39 held-out comparison

**No overall real-corpus answer-quality improvement was demonstrated.** All
14 selected pairs completed using **33 of at most 60 new API attempts**. Grounded
blocked four unsafe text-table answers, but also rejected five supported drafts.
Its one extra search did not recover an answer into the sent context. The
semantic auditor saw only four supported drafts; added protection against genuine
incorrect eligible drafts remains unproven. No factually wrong final claim was
observed against the original PDF in either mode.

This report separates three questions: whether the final claim is true against
the original PDF, whether the **actually sent text** supports it safely, and
whether the question was answerable somewhere in the corpus. Those denominators
must not be interchanged. Independent human and vehicle validation remain open.

## Corpus, selection and execution boundary

The unchanged `bmw-e39-2002-phase2b-heldout-v1` contains twelve information needs
with EN/DE/RU formulations. The matching private corpus is the 186-page US
English VIII/2001 manual for model year 2002, with 241 frozen 384/48-token chunks.
Both existing indexes were reused: pinned E5 Small (`baseline`) and BGE-M3 dense,
CPU, original questions, top five initially and the existing single bounded
local top-20 expansion. Corpus/page/chunk digests and index fingerprints were
checked before inference. No reindexing, translation, query rewriting, threshold,
source selection, generator prompt, audit prompt, graph or numeric gate changed.

The main selection is a small balanced partial factorial, not the full matrix:

| Need | Languages | Profiles | Selection purpose |
| --- | --- | --- | --- |
| `seat_height` | EN, RU | E5 Small, BGE-M3 | Successful retrieval; distinguish manual from electric seat controls. |
| `chains_speed` | EN, DE | E5 Small, BGE-M3 | Explicit numeric prose, units, approved equipment and use conditions. |
| `engine_cylinders` | DE, RU | E5 Small, BGE-M3 | Relevant page but lost table layout; frozen text-only safety limitation. |

A supplemental `hood_release` DE pair for each profile was selected from the
**previously frozen retrieval rankings**, before any live answer to that need.
E5 Small's correct page ranked eighth, making a top-five miss and potential
bounded recovery informative; the BGE pair holds the need/language constant.
Execution was conditional on an error-free main stage and at least ten attempts
remaining under the same sixty-attempt ceiling. This is purposive selection to
expose mechanisms, not an estimate of corpus-wide error frequencies or a new
retrieval model-selection experiment. Translations/profile repeats are not
independent information needs.

All inference used Groq `openai/gpt-oss-120b`, temperature zero, JSON mode,
`on_demand`, the unchanged 2,048-token reasoning/output budget, no retry,
fallback, output repair, diagnostic completion or paid/account change. Free /
Current Plan and the organization's 30 RPM / 1,000 RPD / 8,000 TPM / 200,000 TPD
limits were checked in Console. A shared limiter was configured at **6 RPM**;
actual throughput was lower because of proactive TPM waits.

The ordinary byte-based reservation rejected many unmodified BMW contexts
before HTTP. A separate opt-in transport accounting change uses the pinned
local Harmony tokenizer plus 256 input tokens of framing margin and the full
completion budget; `bytes` remains the default. No source/context/output budget
was reduced to fit. On the main selection's local context preflight,
tokenizer reservations ranged 3,437–6,015 tokens, compared with byte estimates
up to 15,631. Downloading tokenizer metadata used no inference attempt or model
weights. See [accounting setup and limits](../groq.md#optional-offline-tokenizer-accounting-for-real-corpus-contexts).

The private runner shared an atomically persisted sixty-attempt ledger across
profiles/segments, reserved each new request before HTTP, restored preceding
known local quota history, and stopped globally on the first provider/local
error. It refused existing session/segment files; completed checks were never
repeated. Every completed mode, actual messages/raw replies and quota state
were checkpointed. Paired order was seeded (`20261026`), with independent live
generation in each mode. The supplemental stage carried forward both quota
history and the last request-start time. No old synthetic live case was rerun.

## Source review and metric interpretation

The implementation agent inspected live final claims, raw drafts, actual sent
sources and citation mappings, and rendered original PDF pages 49, 136 and 168
(and the supplemental hood page). This is **agent review, not independent human
review**, and it is separate from the Groq auditor's output.

A hash-bound additive source review judges every distinct actually sent draft
context. The final context determines the source-relative refusal metrics;
initial contexts remain separately inspectable for recovery. Legacy summaries,
labels, frozen Phase 2 datasets/results and prior Groq reports are unchanged.
See [schema and denominators](grounded-answering.md#additive-sent-source-sufficiency-review).

The engine-table distinction matters: a value can agree with the rendered
original PDF while its short numeric quotation does not establish the model /
quantity / cell relationship safely in flattened text. Such a result is not a
factually wrong number. It is a grounding failure under the existing frozen
`requires_layout` policy, and must not be sold as prevented factual hallucination.

### Why the real recovery attempt failed

A zero-API local retrieval/context-assembly replay exactly reproduced both live
sent-context hashes. It confirmed the correct hood page at **rank 8 of top 20**,
but that page was omitted from the bounded expanded context. Keeping the first
eight hits would require **12,502 characters**, exceeding the unchanged 12,000
character cap; the builder skipped the relevant passage and admitted a later
shorter passage. The actual expanded context was 11,694 characters / 8 sources,
with pages 55, 4, 53, 147, 155, 75, 151 and 7, without page 137.

This is a retrieval miss initially and a **context-assembly loss after retrieval**,
not a generator refusing an available fact. Reporting gold-page retrieval alone
would hide the failure. The live request/source captures are authoritative; the
matching replay is explicitly labelled local analysis, not another live answer.
BGE-M3 retrieved the location initially, but its supported draft was rejected by
the separate numeric-source gate. There was no successful real-corpus recovery
in this stage, unlike the earlier controlled synthetic live recovery example.

### Confirmed filter limitation; workflow preserved

`_unreliable_numeric_source` classifies a source as unreliable when a physical
line contains multiple numbers without one of a narrow list of verbs. Normal
wrapped prose with two equivalent speed units triggers this heuristic. The
check is also applied before determining whether the claim itself is numeric,
so unrelated closing-height prose in the hood source blocks a location claim.
The captured drafts and original page renderings establish these five false
positives. They are local-filter failures, not generator refusals or auditor
rejections. No speculative prompt/graph/filter change was made during comparison.
A narrowly designed fix needs to preserve damaged-table, number-word,
unit-adjacent, model/applicability and source-retention safeguards; changing the
workflow now would not retrospectively improve these recorded live results.

## Testing semantic audit with genuine bad drafts

This run's local table gate and source-relative labels must not be used as
proof that the semantic auditor prevented false claims. To measure the auditor
itself in a future separately authorized, budgeted stage:

1. Prospectively retain **every naturally generated first draft**, including
   those ultimately rejected, with exact question, source set, complete live
   response, provider/model/settings, code/index hashes and token/timing data.
   Do not manufacture errors by replacing live replies, weakening prompts or
   injecting the adversarial fixture `script` into model inputs.
2. Have independent reviewers label factual truth, quotation validity,
   entailment, missing conditions/applicability and completeness before seeing
   auditor verdicts. Separate factual errors, unsupported true statements,
   incomplete answers and intrinsically insufficient contexts. Retain unresolved
   cases without guessing. Use a predeclared consecutive sample plus explicit
   hard strata; publish denominators and selection criteria, not just failures.
3. Separate drafts eligible for semantic audit (schema/citation/numeric checks
   pass) from drafts already stopped by local gates. A genuine unsupported draft
   from a table that the gate blocks cannot demonstrate the audit's added value.
4. For natural eligible drafts already captured, an **auditor-only replay** can
   reuse their exact unchanged draft and source payload. Label it recorded-draft
   replay rather than a fresh end-to-end live run; spend/record only its new
   audit requests. Compare reject/accept decisions against independent labels,
   with supported control drafts to measure false rejection. Never replace an
   observed live generation result with a replay outcome in the original report.
5. Also run a fresh bounded end-to-end comparison on new held-out needs to test
   actual final-answer benefit, recovery and extra false refusals. Report harmful
   draft false acceptance and supported-draft false rejection separately, along
   with genuine-error counts, confidence limitations, calls, searches and tokens.
   If no naturally incorrect eligible drafts occur, the prevention denominator
   is zero; keep the conclusion **not demonstrated**. Synthetic regressions
   remain software tests and are reported separately.

The original natural engine drafts are useful private grounding-policy examples,
but their numbers agree with the original PDF and the numeric gate blocks them.
They do not supply the missing evidence of semantic-audit detection of genuine
factual/applicability mistakes that pass local validation.

## Independent review packet and remaining Phase 3 acceptance

The public [results artifact](groq-20261026-e39-results.v1.json) retains original
case/language/mode/trial identities, answer/request/response/source-set hashes,
unchanged legacy metric definitions, additive source labels and explicit agent
provenance, per-profile reports, searches/calls/tokens/timing, runtime source and
index identities, quota observations and private checkpoint/capture/review
hashes. First-draft request hashes match between modes in every pair.

The local private entry point is
`output/private/groq/e39-20261026/review/index.html`: eight per-segment HTML
packets cover all 28 final answers, original candidates, every actual sent source
set and raw reply. Unfilled claim/source review JSON templates and a rubric
support independent rescoring with no API calls. The packet links to the local
original PDF and relevant private page renderings; no PDF copy, extracted text,
private capture, absolute private path or packet is published. Original
checkpoints remain unchanged and unscored, so reviewers can judge them before
viewing agent-scored exports. Reviewer identity/provenance is retained per row;
a partial human review cannot promote untouched agent judgments to human ones.

Before Phase 3 can be considered complete:

1. Independently review the 28 answers/drafts/source sets, translations,
   applicability, completeness and the distinction between factually correct
   table values and permitted text grounding. Reconcile disagreements explicitly.
2. Fix and regress the confirmed numeric-source false positives without weakening
   existing table/number-word/unit-adjacent protections. Verify captured natural
   inputs locally and then run a **new**, separately identified/budgeted live
   sample; keep this historical comparison intact.
3. Resolve the demonstrated context-assembly loss conservatively, preserving
   previously seen safety constraints and bounded context. Test actual sent
   evidence sufficiency, rather than gold-page retrieval alone, before claiming
   real recovery works. This stage does not justify indiscriminately discarding
   old sources, enlarging budgets or tuning against held-out answers.
4. Obtain genuine erroneous **audit-eligible** live drafts and independent labels
   as described above. Measure both harmful acceptance and supported-draft false
   rejection. Four accepted correct seat drafts are not evidence of extra
   semantic hallucination protection.
5. Validate wider, balanced EN/DE/RU needs and both matching profiles, with
   predeclared sampling and enough observations for the intended claim. This
   sample has four distinct needs and incomplete language coverage per need;
   no general accuracy, model superiority or vehicle applicability is established.

The evaluation ambiguity is addressed; **Phase 3 quality acceptance remains
open**. Current LangGraph's measurable real-document benefit here is its local
conservative table barrier. It did not improve final information coverage and
introduced five local-filter false refusals at additional resource cost. No
merge, tag or GitHub Release is performed.
